Función recursiva bien planteada

Necesita dos cosas: al menos una invocación a sí misma y, ANTES de esa invocación, una condición de corte (caso base) que resuelva el caso trivial sin recursión. Además, en cada llamada el problema se tiene que achicar hacia ese caso base.

def factorial(n):
    if n == 0:          # caso base: va primero
        return 1
    return n * factorial(n - 1)   # n se achica
Oficial: "al menos una invocación a sí misma y antes de esas invocaciones una o más condiciones de control". Salió dos veces en el mismo P5 2021.
Trampa: si la llamada recursiva va antes del if n == 0, nunca corta → recursión infinita y desborde del stack. Y con factorial(-4) la condición n == 0 nunca se cumple: también desborda.

Definición recursiva: la buena tiene caso base + parte recursiva. Bosque = vacío, o árboles + otro bosque. "Un bosque es un bosque" es circular; sin el "puede estar vacío" hay regresión infinita.

Potencia: aⁿ = 1 si n == 0; aⁿ = a · potencia(a, n-1) si n > 0 (se achica el exponente, no la base).

Stack segment

  • Funciona como una pila (LIFO).
  • Lo usa toda invocación a función, sea recursiva o no: se llena con la cascada de llamadas y se vacía al regresar.
  • La recursión puede ocupar más memoria que la versión iterativa (no siempre).
Trampa: "la recursividad usa memoria ROM" o "siempre ocupa más memoria" son falsas. "Solo la usan las recursivas" también es falsa.

Menú recursivo: funciona, pero cada vuelta pide memoria de stack: es preferible la versión con ciclo.

¿Cuándo conviene la recursión?

Cuando la versión iterativa sería mucho más compleja: recorrer estructuras no lineales (árboles, grafos) y generar fractales. No alcanza con que exista una definición recursiva: Fibonacci es el contraejemplo.

Ackermann

def ackermann(m, n):
    if m == 0:
        return n + 1
    elif n == 0:
        return ackermann(m - 1, 1)
    else:
        return ackermann(m - 1, ackermann(m, n - 1))

Termina siempre, pero crece de forma explosiva: aun con m = 4 la cascada de llamadas desborda el stack. Ejemplos: A(1, n) = n + 2 · A(2, 1) = 5.

Seguimiento: ¿antes o después de la llamada?

def mostrar(n):
    if n > 0:
        mostrar(n - 1)
        print(n, end=' ')   # a la vuelta → 1 2 3

Lo que está después de la llamada se ejecuta "a la vuelta" (orden inverso al de las llamadas). Si el print va antes, sale 3 2 1.

Fusión de arreglos (merge)

Toma dos arreglos ya ordenados (de menor a mayor) y arma un tercero ordenado de n + m casillas comparando de a uno. Cuando uno se agota, copia el resto del otro sin comparar.

Trampa (te pasó): la fusión no ordena los arreglos originales primero. Si no vienen ordenados, el resultado no queda ordenado.

Shellsort

  • Arma subconjuntos ordenados con elementos a distancia h > 1 y termina con h = 1: ahí es una inserción simple y es la que garantiza el orden.
  • Serie de la ficha: h = 3*h + 1 → 1, 4, 13, 40, 121… (para n = 100 usa 13, 4, 1).
  • Es difícil de analizar: depende de la serie de incrementos.
Trampa: la serie {…16, 8, 4, 2, 1} es mala: los subconjuntos tienen casi los mismos elementos. Y la pasada con h = 1 es obligatoria (vos marcaste "no es obligatoria").

Quicksort sale seguido

  • Mejora sobre Burbuja: acelera tanto a los menores como a los mayores (recorre desde los dos extremos).
  • Peor caso O(n²): el pivot es siempre el menor o el mayor de la partición → árbol de llamadas de altura n.
  • Caso promedio: altura log n, tiempo O(n log n).
  • Pivot primero/último = mala idea: con arreglos ordenados o casi ordenados cae en el peor caso.
  • Lo recomendable: mediana de tres (primero, central y último). get_pivot_m3 es O(1): no tiene ciclos.
  • La versión básica de la ficha usa la casilla central: v[(izq + der) // 2].

Divide y Vencerás

Divide en subconjuntos de tamaño aproximadamente igual (n/2, n/3…), procesa cada uno con recursión y une los resultados. No se puede aplicar a cualquier problema.

La eficiencia depende de: cantidad de invocaciones recursivas, tiempo para procesar cada subconjunto y factor de achicamiento.

proceso(partición):
    adicional()          # O(n)  →  total O(n·log n)
    proceso(partición/2)
    proceso(partición/2)
Oficial: algoritmos D&V = Quicksort y Mergesort (no Shellsort, no Heapsort).

Factores de eficiencia y casos

Oficial (P5 2021): factores = tiempo de ejecución, consumo de memoria y complejidad aparente del código fuente. Los dos más usados: tiempo y memoria. La interfaz de usuario NO.
  • Peor caso: la configuración de datos más desfavorable.
  • Caso promedio: datos aleatorios (ni favorecen ni desfavorecen).
  • Conteo exhaustivo: la fórmula exacta de operaciones críticas (ej: ½(n² − n)). Análisis asintótico: cómo se comporta para n muy grande.
  • Orden de complejidad: familia de funciones que se comportan asintóticamente igual.
  • Problemas intratables: solo se conocen algoritmos exponenciales O(2ⁿ).

Reglas prácticas

  • Se queda el término que más crece y se tiran las constantes: 3n³ + 5n² + 2n1.5 → O(n³).
  • Bloques en secuencia: manda el mayor (O(n²) seguido de O(n³) → O(n³)).
  • Ciclo interno de vueltas fijas (range(10)) no multiplica por n: es una constante.
  • for i in range(n+1): for j in range(m+1) → O(n·m), no n².
  • Por qué los simples, siendo todos O(n²), tardan distinto: Big O descarta constantes y términos menores.

Tipos abstractos

Abstracción de datos: qué datos representan al tipo (Fecha → registro con año, mes y día). Abstracción funcional: qué procesos se hacen con esos datos (buscar, reservar, liberar, modificar).

Pilas (stack.py) · LIFO

  • push(x) agrega al frente (final de la list) · pop() saca el del frente · peek() lo mira sin sacarlo · is_empty().
  • pop() o peek() con la pila vacía retornan None (sin error).
  • Aplicación principal: procesar datos en orden inverso (control de capicúas: apila la mitad izquierda y la compara con la derecha; si el largo es impar, saltea el caracter central).

Sacar el 3º de la pila y dejar los dos de arriba igual: n1 = pop(); n2 = pop(); x = pop(); push(n2); push(n1) (se devuelven en orden inverso).

Invertir una pila con p2 y p3: hacen falta 3 traspasos (p → p2 → p3 → p). Cada traspaso invierte.

Colas (queue.py) · FIFO

  • add(x) al final · remove() saca el primero · peek() mira el primero.
  • Aplicación: procesar en el mismo orden de llegada.
Trampa: pasar de cola a cola no invierte. Para invertir una cola: cola → una pila → cola.

Cola de prioridad (sale siempre el menor): list con inserción ordenada de menor a mayor y eliminación del primero.

Árbol binario: definición y términos

Puede estar vacío o tener una raíz de la que salen dos subconjuntos: a) con intersección vacía y b) que son a su vez árboles binarios (definición recursiva). La regla a) es la que impide que un nodo tenga dos padres.

  • Nivel: arcos para llegar al nodo desde el arco de entrada a la raíz → la raíz está en el nivel 1.
  • Altura: el número de nivel máximo.
  • Balanceado (idea intuitiva): altura mínima posible (cerca de log₂ n).

Árbol binario de búsqueda (tree.py)

  • Menores a la izquierda, mayores a la derecha. add() no acepta repetidos (retorna False).
  • Búsqueda: 1 comparación por nivel → cuesta la altura h. O(log n) solo si h = O(log n); O(n) en el peor caso (diagonal, por ejemplo si se insertan datos ordenados).
  • Borrar un nodo con dos hijos: se reemplaza con el mayor del subárbol izquierdo.
  • Regla relajada (iguales a la derecha): iguales a la raíz → diagonal con los izquierdos nulos; dos iguales pueden quedar a varios niveles de distancia.

Grafos: tipos y términos

  • Dirigido: sociograma, plan de estudios, cañerías. No dirigido: rutas entre ciudades, rutas aéreas. Un no dirigido es un dirigido simétrico.
  • Ponderado: cada arco tiene un peso (distancia, peaje).
  • Puede haber nodos aislados, varias componentes conexas y varios caminos de distinta longitud entre dos nodos.
  • Camino de longitud k: secuencia de k arcos. Ciclo: camino que vuelve al mismo nodo. Auto ciclo (bucle): arco de un nodo a sí mismo. Los ciclos están permitidos.
  • Grado de entrada: arcos que llegan · de salida: arcos que salen · grado: todos los incidentes.
Trampa (te pasó): en el plan de estudios no son aceptables los ciclos ni los auto ciclos. Las materias sin arcos de entrada (primer año) sí son válidas.

Ávidos y cambio de monedas

  • Ventaja: si la regla es correcta, es simple y rápido. Lo difícil es demostrar que la regla es correcta.
  • greedy_change ordena las monedas de mayor a menor y usa siempre la más grande que entre. Si hay una moneda igual a x, retorna 1.
  • Falla en sistemas no canónicos: con {1, 5, 10, 23, 50} y x = 30 da 4 (23+5+1+1) y lo óptimo es 3 (10+10+10).
Oficial: lo único cierto es que la moneda de 1 centavo es exigible con cualquier algoritmo.
Trampa (te pasó): que el ávido no dé el óptimo no significa que el problema no tenga solución: la dinámica lo resuelve.

Programación dinámica: dinamic_change

  • prev[v] = mínimo de monedas para el monto v. Se calcula con prev[v - moneda] + 1.
  • Las monedas mayores que v se saltean (continue).
  • Retorna prev[x].
  • No importa si coins está desordenado.

Ocho Reinas (backtracking)

  • rc[col] = fil: una reina por columna. qr marca filas libres (8).
  • Diagonales normales (como la principal): col − fil constante en [−7, 7] → índice dn = (col − fil) + 7.
  • Diagonales inversas: col + fil constante en [0, 14] → índice di = col + fil.
  • 15 + 15 = 30 diagonales; qid y qnd tienen 15 casillas.
  • El while de intend() corta cuando res es True o fil es 7.

Cómo detectar una rc incorrecta: fila repetida, o dos columnas con el mismo col − fil o el mismo col + fil.

Oficial: incorrectas = [3, 5, 7, 0, 5, 1, 2, 4] (fila 5 repetida) y [2, 0, 7, 4, 5, 1, 6, 3] (columnas 3 y 4 en la diagonal normal −1). Válidas: [4, 7, 3, 0, 2, 5, 1, 6] y [5, 3, 6, 0, 7, 1, 4, 2].
